# Reflection

This mini project helped me understand how version control can be applied to a Power BI development workflow. Copilot was useful as a starting point for thinking through DAX measures such as month-over-month growth and city-level ranking. However, the suggestions still needed to be reviewed against the actual semantic model, especially the table names, column names, existing measures, and filter context. I found that DAX generated by an assistant should not be accepted without checking whether it matches the model structure and produces the intended result.

The version-controlled workflow was different from a normal Power BI lab because the project was maintained as a Power BI Project and stored in GitHub. Instead of treating the report as one finished file, the development process could be tracked through commits. This makes changes easier to review and provides a record of how the model, measures, dashboard, and documentation developed over time.

The workflow also encouraged more careful organization. The star schema, DAX measures, report, README, notes, and reflection were treated as separate parts of the project rather than being completed as one final file. Overall, the project showed how Power BI, GitHub, VS Code, and Copilot can be combined to make a BI solution more structured, reviewable, and auditable.
